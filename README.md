# Week1Task13 — агент с явной многослойной моделью памяти и конечным автоматом задач

Локальное Python-приложение: библиотека агента и CLI-интерфейс. Агент —
отдельная объектная сущность, инкапсулирующая работу с LLM и четырьмя
независимыми слоями памяти.

Слои памяти:

- **profile** — предпочтения пользователя по стилю, формату, ограничениям
  (`memory/<agent>/profiles/<name>.json`, активный — в
  `memory/<agent>/active_profile.txt`);
- **short-term** — лог диалога в рамках активной задачи (`memory/<agent>/short_term.json`);
- **working** — данные текущей задачи (`memory/<agent>/working_<task_name>.json`);
- **long-term** — решения и знания (`memory/<agent>/long_term.json`).

Подробное описание модели памяти — в [MEMORY_MODEL.md](MEMORY_MODEL.md).

## Установка

Требуется Python 3.10+.

```bash
python -m pip install -r requirements.txt
```

Зависимости: `httpx`, `rich` (rich опционален — CLI работает и без него).

## Конфигурация

Файл `config.json` в корне проекта описывает провайдеров и агентов (см. пример в
репозитории). Приоритет источников значений: **CLI-аргументы → env → config.json**.

```jsonc
{
  "default_agent": "assistant",
  "providers": {
    "deepseek": { "type": "openai_compatible" }
  },
  "agents": {
    "assistant": {
      "provider": "deepseek",
      "model": "deepseek-chat",
      "endpoint": "https://api.deepseek.com",
      "api_key_env": "DEEPSEEK_API_KEY",
      "system_prompt": "...",
      "temperature": 0.7,
      "max_tokens": 1024,
      "top_p": 1.0,
      "top_k": 50,
      "memory_dir": "memory/assistant"
    }
  }
}
```

## Переменные окружения

- `DEEPSEEK_API_KEY` — API-ключ (имя задаётся полем `api_key_env` в конфиге).
  Ключ **никогда** не хранится в `config.json`.
- `DEFAULT_AGENT` — переопределяет `default_agent` из конфига (env > config).

## Запуск CLI

Интерактивный режим:

```bash
python cli.py
python cli.py --agent coder
python cli.py --config path/to/config.json
```

Одноразовый режим (один запрос — один ответ):

```bash
python cli.py --prompt "Привет!"
```

В интерактивном режиме строки, начинающиеся с `/`, обрабатываются как команды,
остальные — как сообщения агенту.

## Профили

Профиль — отдельный слой памяти, более приоритетный, чем long-term. Он описывает
пользователя: предпочтения по стилю, формату, ограничениям. У каждого агента —
свой набор профилей; активный профиль хранится в файле
`memory/<agent>/active_profile.txt`.

| Команда | Описание |
| --- | --- |
| `/profile list` | список профилей агента (активный помечен) |
| `/profile current` | показать имя активного профиля |
| `/profile show [<name>]` | показать содержимое профиля (по умолчанию — активного) |
| `/profile new <name>` | создать профиль с пустыми обязательными полями |
| `/profile switch <name>` | сделать профиль активным (обновляет `active_profile.txt`) |
| `/profile del <name>` | удалить профиль (если он был активным — активный становится не задан) |
| `/profile set <name> style\|format\|constraints <value>` | задать поле профиля |
| `/profile unset <name> style\|format\|constraints` | очистить поле профиля (пустая строка) |
| `/profile add-note <name> <текст>` | добавить заметку в `notes` |
| `/profile del-note <name> <index>` | удалить заметку по индексу |

Если активного профиля нет — слой просто не подмешивается в промт. Включить или
выключить слой в промте можно командой `/memory usage profile on|off`
(по умолчанию — on).

## Команды

Полный список с описаниями — `/help`.

| Команда | Описание |
| --- | --- |
| `/agents` | список агентов, активный помечен |
| `/agent <name>` | переключить активного агента |
| `/task new <name>` | создать и активировать задачу (short очищается) |
| `/task switch <name>` | активировать существующую задачу (short очищается) |
| `/tasks` | список задач агента |
| `/task current` | текущая активная задача |
| `/profile ...` | управление профилями (см. раздел «Профили») |
| `/memory show long\|working\|short` | показать записи слоя |
| `/memory add long decision\|knowledge <текст>` | добавить в long |
| `/memory add working <текст>` | добавить в working (нужна задача) |
| `/memory add short <текст>` | добавить в short |
| `/memory del <layer> <id>` | удалить запись по ID |
| `/memory clear short\|working\|long` | очистить слой |
| `/memory files` | пути к файлам памяти, папке профилей и файлу активного профиля |
| `/memory usage profile\|long\|working\|short on\|off` | вкл/выкл слой в промте |
| `/debug on\|off` | показывать записи (в т.ч. поля и заметки профиля), попавшие в промт |
| `/metrics on\|off` | показывать токены и время |
| `/prompt_save on\|off` | спрашивать после ответа, куда сохранить (CLI) |
| `/help` | список команд |
| `/exit` | выход |

## Конечный автомат задачи (FSM)

Задаче можно задать последовательность **этапов** (state machine). Пока этапов
нет — задача работает как обычный диалог с рабочей памятью. «Этап», «текущий
шаг» и «ожидаемое действие» — одно и то же (один уровень).

Этап состоит из: `name` (короткое имя для команд), `description`, `condition`
(условие завершения на естественном языке, оценивает LLM), `expected_action`,
`status` (`pending | active | completed`), `order`.

| Команда | Описание |
| --- | --- |
| `/task stages list` | показать этапы (порядок, описание, условие, статус; активный помечен) |
| `/task stages set` | полностью перезаписать набор этапов (интерактивно); очищает рабочую память, первый этап — active |
| `/task state` | показать состояние: этап, ожидаемое действие, условие, статус, пауза/завершено |
| `/task next` | принудительно перейти на следующий этап |
| `/task back` | вернуться на предыдущий этап |
| `/task goto <name>` | перейти к конкретному этапу |
| `/task check` | вручную запустить проверку условия текущего этапа |
| `/task pause` | поставить задачу на паузу (автомат не двигается, проверки и блок состояния отключены) |
| `/task resume` | снять с паузы |

После каждого ответа агента автоматически запускается проверка условия текущего
этапа через отдельный вызов LLM. Если условие выполнено — CLI спрашивает
«Перейти к следующему этапу? [y/n]». На последнем этапе задача помечается
завершённой, а рабочая память очищается.

### Пример задания этапов

```text
[assistant]> /task new mvp
[assistant]> /task stages set
Сколько этапов задать? 3
  Этап 1/3 — имя (короткое, для команд): planning
  Описание этапа: Составить план реализации
  Условие завершения (естественный язык): План согласован с пользователем
  Ожидаемое действие: Предложить план и получить подтверждение
  Этап 2/3 — имя (короткое, для команд): execution
  Описание этапа: Реализовать код по плану
  Условие завершения (естественный язык): Код написан и запускается
  Ожидаемое действие: Написать работающий код
  Этап 3/3 — имя (короткое, для команд): validation
  Описание этапа: Проверить результат
  Условие завершения (естественный язык): Результат проверен пользователем
  Ожидаемое действие: Показать результат и получить подтверждение
Набор этапов задан: planning, execution, validation. Рабочая память очищена, первый этап активен.

[assistant]> /task state
Состояние задачи:
  Этап: planning
  ...
```
